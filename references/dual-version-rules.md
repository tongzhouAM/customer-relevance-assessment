# 双版本产出规则：内部评估版 × 客户汇报版

> 标配：每次客户评估**必须产出两个版本**——内部评估版（决策工具）+ 客户汇报版（说服工具）。
> 客户版**不是内部版删敏感项的删节版**，而是换姿态重写。本文是转化规则与自检清单。

---

## 一、根本区别（一句话版）

- **内部版是镜子**——照出客户真实的样子，回答"我们要不要把时间押在这里"。
- **客户版是窗户**——让客户从里面看到自己的机会，以及我们恰好站在那个位置上。

| 维度 | 内部评估版 | 客户汇报版 |
|------|-----------|-----------|
| 服务的决策者 | 我们自己（资源分配决策） | 对方决策链（对接人转发给他老板的说服弹药） |
| 本质 | 投资尽调 | 销售前置材料 |
| 视角方向 | 我们 → 客户（审视，博弈视角） | 客户 → 自己（陪他看他的业务走向） |
| 不确定性 | 显式露底（⚠️ 未验证/推断/待实地）——置信度错误=投入错误 | 要么验证后写，要么转化为双方动作（Stage 0 联合确认 / 先实测再承诺） |
| 底牌方向 | 翻他的底牌给我们（决策链/预算风险/竞品格局/渠道策略） | 锁死我们的底牌——技术边界诚实，商业意图保密 |
| 判断密度 | 判断密集（评分/定性/优先级/时间窗口） | 事实+框架密集、判断收敛（让客户自己得出结论） |
| 竞品 | 有名有姓 + 攻击/防御话术 | 匿名化为"典型做法"，攻击变成差异化对照表 |
| 检验标准 | 看完知道"下一步做什么、投入多少、何时放弃" | 对接人能否一字不改转发老板；老板看完想不想见我们 |

## 二、章节转化对照表（内部版 → 客户版）

| 内部版章节/要素 | 客户版处理 |
|----------------|-----------|
| 标题"XX合作评估" | 改"业务相关性分析（客户交流版）"——评估味→对话味 |
| 评估结论（⭐评分+定性判断） | **相关性结论**（"高度相关，建议从 X 场景启动"）——不给客户的事业打星 |
| Executive Summary（4 关键发现） | 相关性总览（4-5 关键判断）——判断措辞从"他的痛"改"他的业务走向 × 我们的能力" |
| 公司画像 + 供应链压力点 | 业务画像保留（体现做了功课）；压力点中性化为"业务单元与我方方案的关联"，**不引用其财务弱点**（净利下滑/亏损等一律删除） |
| 流程×方案关联表 | 保留（相关性核心），语气从"可替代空间"改"互补价值" |
| 场景匹配矩阵 | 相关性矩阵：列名"需求急迫度"→"需求相关度"；"行动建议"→"合作方向"；评级保留 🔴🟡🟢 但不出现"最优切入/打"类措辞 |
| P0 场景深度展开 | 首选/试点场景展开：痛点→"现状与挑战"（行业通识+联合确认兜底）；市场参照删除竞品名与内部定价模式编号，保留行业 ROI 区间 |
| 差异化定位（攻击话术） | "与典型方案的差异"对照表（竞品全部匿名化） |
| 有利/不利因素对照 | 删除——有利因素已化入关键判断；不利因素化入"需要联合确认的事项" |
| 六维综合评分 | **删除**（竞争门槛/进入难度是博弈视角，绝不可见） |
| 决策链推测 + 接触路径 | **删除**，转化为"建议合作路径"（Stage 0 → 试点 → 双轨 → 推广） |
| 行动方案（P0/P1/P2 我们做什么） | 合作路径（我们一起做什么）+ **待双方联合确认清单**（把情报缺口转成联合确认动作） |
| 风险与注意事项 | 删除，转化为口径声明 + 影子期实测验收 + "先实测再承诺" |
| 假设验证结果 | 删除（内部质询过程）；其中"待验证项"转入联合确认清单 |
| 反面观点与回应 | 删除 |
| 参考资料 T1/T2/T3 | 简化为"参考来源（公开信息）"3-5 条，不带内部文档引用 |

## 三、客户版硬红线（出现即事故）

1. 内部型号与研发代号（硬件/算法/软件版本号等）——一律用功能通用描述（如"自研传感器 / AI 算法模型 / 自研采集终端"，按你的产品域改写）
2. 内部定价模式编号与分档——只可用行业通用 ROI 区间（回收期基准、检测成本下降量级、人工替代占比区间）
3. 客户财务弱点（净利下滑/亏损/砍预算风险）
4. 竞品具名 + 攻击话术
5. 内部策略（渠道传导、决策链、接触路径、招标监测、投入上限）
6. 历史废弃口径数值——统一只用我方方案画像（vendor-profile）中登记的当前对外口径，不混用新旧数字
7. "评估味"措辞：进入难度、付费意愿、值不值得打、最优切入等

## 四、客户版三项诚实底线（不许包装掉的）

1. **技术边界**：覆盖不到的场景/性能上限明写 + 升级路线图（句式："X 以上先实测再承诺，扩展在路线图中"——按你的产品域填写具体参数）
2. **效果承诺**：不作无条件承诺，锚定"影子期实测验收"
3. **口径可审计**：对外量化口径必须可复现（标定方法、测试条件、适用边界写清）；不做无标定的换算或类推

## 五、客户版自检清单

- [ ] 标题与全文无"评估/打分/进入难度"类内部措辞
- [ ] 相关性结论替代评分；关键判断 4-5 条，全部站在客户业务视角
- [ ] 章节结构对齐评估骨架但措辞已转写（画像→流程关联→场景矩阵→场景展开→合作路径→能力案例→下一步）
- [ ] 联合确认清单存在（把内部情报缺口转为双方动作）
- [ ] 硬红线 7 条逐项过一遍（内部型号/定价分档/财务弱点/竞品具名/内部策略/废弃数值/评估味措辞）
- [ ] 诚实底线 3 条在文中有落点
- [ ] 案例具名状态按用户当次指示（默认脱敏）
- [ ] 检验：对接人能否一字不改转发给老板？
- [ ] MD + HTML 双格式保存至 `{输出目录}/{客户简称}-业务相关性分析-客户版-{YYYY-MM-DD}.{md,html}`

## 六、参考实例

- 内部版 + 客户版成对样板命名：`{输出目录}/{客户简称}-合作评估-{YYYY-MM-DD}.{md,html}`（内部）与 `{客户简称}-业务相关性分析-客户版-{YYYY-MM-DD}.{md,html}`（客户）
- 先例：用户提示客户关注某业务线后，该业务维度升为主线之一（客户版主线可按对接人关注点调整）
